# qbe.mbt 1:1 复刻 QBE 任务计划

目标：接管项目，把前端魔法代码全量现代化 + 补全 loadopt，然后 1:1 复刻 qbe 后端
直至产出与参考 `obj_qbe.exe` 逐字节一致的 .s 汇编。每阶段用 compare.py 验证，
完成后 git commit 便于回滚。

### 阶段 0/1 期间额外修复的真实 bug（前人代码缺陷）
- memopt.mbt: Use 用 b.ins[u.ins_idx] 跨块索引越界 -> 按 u.blk_id 定位指令；
  store->copy 的 cls 硬编码 Kw -> 用合并类 k；loadsw/loaduw 在 k!=Kl 时漏落入 Oload 分支
- ssa.mbt phiins: FIFO worklist -> LIFO；phi 追加 -> 前插；phi 类硬编码 Kw -> k
- ssa.mbt renblk: 后继 phi 填充用 p.to.tmp_val()（新 tmp id 越界）-> 用 visit 取原始 id
- cfg.mbt filldom: dom 孩子按块 id/RPO 构建 -> 按定义序（C link order）
- cfg.mbt fillrpo: 未删除不可达块 -> 增加 DFS 后清理 + phi 参数清理（C edgedel）
- ssa/use.mbt loadsz: Oload 写死 8 -> 按类宽 KWIDE(cls)?8:4
- types/fn.mbt newtmp 编号: 按 Fn 存储 -> 模块级共享计数器（C static int n 跨函数累计）

## 关键风险
- 逐字节一致陷阱：id0 跨函数递增、FP stash 全局态、slot() 位字段符号扩展（MoonBit 需手写 sign-extend）、framesz 的 rclob 奇偶、omap 线性搜索匹配优先级（Ki/Ka/具体 cls）
- 全局状态：C 用 static 的 id0/stash/gasloc/gassym 在 MoonBit 无对应物 -> 统一收进 Context 驱动对象，阶段 4 起贯穿
- 已有实现可能隐含 bug：filllive、renblk 的栈管理在阶段 1 现代化时必须以参考输出为基准核对，避免"优化"引入偏差
- 建议每完成一个阶段即 git commit
