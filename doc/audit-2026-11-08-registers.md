## Confirmed defect and bounded repair

### REG-1: spill costs interpreted signed, and physical sentinel weakened (fixed)

- C: vendor/qbe/all.h:343 declares Tmp.cost as uint. spill.c:65 uses UINT_MAX for physical registers; spill.c:108–112 compares ca/cb as uint, not signed int.
- Port baseline: types/tmp.mbt:141 stores cost as Int32; spill/fillcost.mbt:61–64 substitutes 2147483647 for UINT_MAX; spill/spill.mbt:83–88 uses signed relational comparison.
- Concrete trigger: two virtual temporaries with unsigned costs 3000000000 and 1, one available register. The large value is generated by three tmpuse calls at loop weight 1000000000 (nine nested loops, without overflowing the signed loop-weight multiplier). Port stores -1294967296 and spills the expensive temporary. Upstream ranks 3000000000 ahead of 1. This is observable allocation/stack traffic divergence, not a proven wrong-result program.
- Independent physical-boundary trigger: virtual cost INT_MAX ties the weakened physical cost, where upstream must prioritize UINT_MAX. With uint costs 0xfffffffe and 0xffffffff the ordering/equality must likewise match upstream. A tie permutation can expose an invalid attempt to spill a physical register; this secondary crash consequence was not independently reproduced and is not claimed as proven.
- Repair: spill/spill.mbt:83–85 now reinterprets both stored cost words as UInt before comparison. spill/fillcost.mbt:61–62 now stores -1, the Int32 bit pattern of UINT_MAX. Cost accumulation is deliberately unchanged: native Int32 addition wraps to the same 32-bit word as C uint addition. The regression exercises actual tmpuse accumulation across INT_MAX. rega/prio2 is deliberately unchanged: C subtracts two uint words then returns int; the native two's-complement word result agrees with existing Int32 subtraction. Replacing that comparator with an unsigned three-way comparator would change upstream's algorithm.
- New tests: spill/audit_regs_wbtest.mbt:17,39, with helper audit_spill_state:3. First test invokes actual tmpuse and limit, checks retained membership and assigned stack slot; second invokes actual fillcost and tcmp0 at INT_MAX, UINT_MAX-1 and UINT_MAX boundaries.
- RED: moon test --target-dir build/audit-registers -p azhzx/qbe/spill -f 'audit registers:*' -> exit 2, 2 tests, 0 passed, 2 failed. Expensive membership was false; physical comparator returned 0 instead of -1. An earlier attempt exited 1 due to a transient concurrent parser/data.mbt:332 syntax error, not due to the regression; lead repaired it before the genuine RED.
- GREEN: identical command -> exit 0, 2/2. Full scoped suites: moon test --target-dir build/audit-registers -p azhzx/qbe/live -p azhzx/qbe/spill -p azhzx/qbe/rega -> exit 0, 14/14. Existing warnings remain (unused variables, deprecated @ref.new, dependency warnings); no clean-warning claim.
- Upstream expected behavior is directly established by uint declaration/comparator. A minimized textual SSA oracle reproduction for this high-cost defect has NOT been run; regression is a direct whitebox state/algorithm test, not an end-to-end C differential run.

## Field, width, sentinel and identity audit

- SpillState.fn_ is the shared current Fn, replacing C static tmp and function argument; buf replaces insb/curi; fst optional aliases caller preference set intentionally; ntmp, locs, slot4, slot8 are signed 32-bit as C int; mask contains two distinct BSet objects. Dynamic scratch/cached-array lifetimes differ but each copy is explicit before destructive intersection.
- RMap.t/r/w each have Tmp0=64 slots, n is signed count, b holds virtual presence AND physical occupancy. rcopy copies storage, never aliases it. rega_dopm snapshots t/r/n only because rfind is the sole reader of the snapshot. RState.regu uses UInt64 matching bits; pm holds immutable PmEntry fields, each appended entry replaces one array cell. Shared default record from Array::make is never mutated. npm/cur_loop signed semantics match C; stmov/stblk are Int32 words vs uint but host debug %d observes same word until impractically large counts.
- Ref enum equality corresponds to type+29-bit C val on well-formed refs. -1 sentinels used for slots, hints, absent mappings, visits and successor ids are preserved; zero is a separate no-wait/no-consensus sentinel. RCall checks via call_val>=0 agree with valid 29-bit encoded calls. Out-of-range handcrafted RCall values are not covered by C parser equivalence.
- All 64-bit register shifts/complements are UInt64; first bitset word is exactly physical range. Normal temp indices fit positive 29-bit Ref payloads, so signed iteration bounds agree with C uint loops. Final slot alignment and wide/narrow packing remain signed C-int operations. Extremely large slot/loop sizes causing C signed overflow are not assigned an invented mathematical semantics.
- Block pointer identity is stable blks index; RPO id is separate and correctly used for sorting, backedges, and beg/end. Def-order is linked-chain order, not raw blks order. PhiArg.blk_id identity checked in liveon and phase4. Field reads/writes through Blk/Tmp/RegHint/Addr mutable records intentionally share state.
- Ins mutable records are pushed by reference, unlike C emiti's value copy. For normal parsed IR, each instruction object is unique. In spiller the source is no longer mutated after emit; in rega the currently emitted instruction changes its original object, but subsequent backward scanning only reads earlier unprocessed objects. Copy-run detection does not inspect a processed object. Mem base/index are intentionally shared exactly like C Mem*. Thus source ownership transfer is safe for ordinary pipeline IR. Handcrafted APIs that place the SAME Ins object in multiple instruction positions are not proven safe; this is a representation contract gap, not a demonstrated parser-origin bug. No speculative clone patch was made.

## Safe differences preserved, with evidence

1. live/live.mbt:77 skips a second identical successor. Both liveon contributions and gen writes are set insertion/union; rerunning changes nothing. Phi args for the same predecessor are scanned in the same order. This is an idempotent optimization.
2. filllive clears chg at the beginning instead of C's mandatory second scan. For well-formed reachable CFGs, successor in changes needing propagation cause an out change on a predecessor; C's unconditional extra scan is redundant for acyclic single-block functions. The invalid single-block jump-to-entry case is rejected upstream (parse.c:686). No valid-input divergence found; adversarial malformed CFG behavior not certified.
3. C tarr capacity cache, file-global scratch, and fixed instruction buffer vs scoped GC arrays affect allocation/performance/limit diagnostics, not ordering when capacities hold. qsort_c keeps upstream platform-specific tie behavior; this audit does not certify libc algorithms on other hosts.
4. rega self-copy pop followed by continue (:579–581) appears to skip upstream hint retry, but a removed self-copy has to==arg1==rf (or rf=-1 for special globals). Allocating the source makes cur.b[rf] occupied, so upstream's !bshas(cur.b,rf) retry condition is necessarily false. No repair warranted.
5. Phase3 omits C nonphi rl[r]==0 -> -1 (:815, C:600–601). That rl entry is never subsequently consumed except by x>0 and a C assertion; both 0 and -1 skip emission. Mappings have distinct physical registers, so no later nonphi reuses that entry. Output-equivalent, diagnostic contract differs.
6. phase4 loops through both successor slots independently, while C stops at first null successor. Well-formed CFG has s2 only with s1; difference only for invalid programmatically constructed CFG. New blocks appended in reverse creation order match C prepended blist exactly.
7. Debug strings returned instead of stderr writes; phase4-delayed mapping formatting reads unchanged mappings. Trailing formatter behavior depends on parser.printfn; pass-specific text/control flow checked, no byte-for-byte debug oracle run.
8. Port extension tmp.reg for debug information does not feed allocation decisions (ralloctry:185–186, rega:693). This scope verifies independence from allocator, not correctness of every downstream debug location.
